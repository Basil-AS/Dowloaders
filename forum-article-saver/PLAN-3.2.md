# План версии 3.2 (рабочая ветка, не влито в main)

Задача: защита от бана на 4PDA, GitHub-репозитории в стиле gitingest, GitHub issues / PR / обсуждения.

## Сделано (в ветке, закоммичено)

**Пауза при ограничениях сайтов**
- `RateLimitError` (429, на 4PDA ещё 403), `PausedError`, `runPool` с остановкой пула на первой ошибке-стопе, `TtlCache` (кэш докачки 30 мин в памяти вкладки).
- 4PDA: ≤3 запросов одновременно, пауза 400 мс, одна проба после паузы сайта, затем пауза; докачка берёт страницы из кэша; защитная страница вместо темы не кэшируется.
- Discourse: те же пауза и докачка. Habr / Reddit: 429 останавливает сохранение (раньше превращалось в предупреждение).
- Popup: статус «Пауза», кнопки «Продолжить» и «Сохранить, что есть» (`partial`), плашка на странице с паузой.

**GitHub** (`src/sites/github/`)
- Дайджест репозитория (`repo.ts`): 3 запроса к API + raw по файлам, маски (gitignore-стиль), лимит размера, оценка токенов, дерево каталогов, `/tree/<ветка>/<каталог>`.
- Issue / PR (`issues.ts`): описание, комментарии, ревью, комментарии к коду. Все issues / PR списком: репозиторные эндпоинты, десятки запросов на сотни записей.
- Обсуждения (`discussions.ts`): GraphQL с токеном (одно и все, ответы вложены, решение отмечено); без токена одно обсуждение читается со страницы (best-effort).
- Фон проксирует запросы только на `api.github.com` и `raw.githubusercontent.com`, токен добавляет сам (в страницу не попадает), POST разрешён только на `/graphql`.
- Настройки: токен (storage.local), маски include/exclude, лимит файла, лимит записей, фильтр состояния. Режимы страницы в popup.

**Проверки на момент коммита**
- `tsc` чистый; e2e `scripts/e2e-github.mjs` 15/15 (GitHub и 4PDA на локальном HTTPS-сервере), старый e2e 31/31.
- Юнит-тесты: 91 из 91 до правок по ревью; после правок один тест (403 на 4PDA) ожидаемо падает, см. ниже.

## Открытые риски

- Дискурс GitHub-страницы без токена (`scrapeDiscussion`) опирается на эвристики вёрстки и проверена только на синтетической странице. С токеном надёжнее.
